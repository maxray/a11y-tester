# A11y Tester

A reference site for WCAG success criteria, paired with a game that tests whether you can spot accessibility failures in real markup.

## Plan

**Content model** — two git-backed collections, edited either as markdown files or through the admin UI:

- **Rules** (`src/content/rules/*.md`) — one WCAG success criterion per file: id, title, level (A/AA/AAA), principle (perceivable/operable/understandable/robust), summary, and a full explanation.
- **Examples** (`src/content/examples/*.md`) — one pass or fail code snippet per file, referencing a rule by id, with a correct explanation of what's right/wrong and a set of plausible wrong-answer distractors.

Splitting rules from examples means a rule page can show several pass/fail pairs, and the game can draw from the examples pool independently of how the reference site presents them.

**Reference site (11ty)** — a rule index (filterable by principle/level) and rule detail pages that render the explanation plus its pass/fail examples with syntax highlighting.

**Admin (Decap CMS)** — available at `/admin`, authenticated via Netlify Identity + Git Gateway, with collections mapped directly to the two content types above. Lets non-technical editors add or edit rules and examples without touching code; edits commit straight to this repo.

**Game (Vue 3 + Pinia)** — built separately with Vite and mounted as an island on one 11ty page. At build time, 11ty generates a `/game-data.json` file from the examples collection; the game pulls 10 random examples, presents each snippet, and asks the player to pick what's wrong from a multiple-choice list (correct answer + distractors, including a "nothing's wrong" trap for pass examples). A Pinia store drives game state (question index, score, answers), persisted to `localStorage` so scores survive a refresh — no backend needed for now.

**Build/deploy** — a single Netlify site. The build runs the Vite build first (game bundle), then the 11ty build, which copies the game's built assets into its own output before publishing.

## Project structure

```
src/
  content/
    rules/       WCAG success criteria (markdown + frontmatter)
    examples/    pass/fail code snippets tied to a rule
  _includes/     11ty layouts and partials
  admin/         Decap CMS config + entry point
  *.njk          site pages (home, game page, game-data.json)
game-app/        Vue 3 + Vite + Pinia game, built independently
```

## Local development

```bash
npm install          # installs root + game-app workspace
npm run build:game   # builds the Vue game into game-app/dist
npm run dev           # eleventy --serve, rebuilds the reference site on change
```

The game reads `/game-data.json`, which is only generated by an 11ty build — run `npm run build:game` and one `npx eleventy` pass before serving if you want live game data locally. For isolated component work on the game itself, `npm run dev -w game-app` runs a Vite dev server against a local fixture.

## Deploying

Netlify build command: `npm run build`. Publish directory: `_site`. Enable Netlify Identity and Git Gateway in the site's dashboard to activate `/admin`. Once the site has a real Netlify URL, update `site_url`/`display_url` in `src/admin/config.yml` to match.
